0.4 — The Vocabulary Bootstrap

In one line: Clear engineering requires crisp definitions — know the difference between parameters, tokens, context, and KV cache.
CORE MODEL PARAMETERS & TOKENS

Parameters ($P$): The learned floating-point weights (e.g. 70B parameters = 70B numbers storing pattern knowledge).

Token: Sub-word atom of text (~0.75 English words). Models operate exclusively on token IDs.

Context Window ($N$): Maximum tokens processed in a single forward pass (e.g., 128k, 1M, 2M).

SERVING & COMPUTE TERMS

Prefill Phase: Processing input tokens in parallel. Compute-bound (FLOP heavy).

Decode Phase: Generating output tokens auto-regressively (1 token at a time). Memory-bandwidth bound.

KV Cache: Memory storing key-value activations for prior tokens to avoid $O(N^2)$ recomputation.

SAY THIS
"Do not conflate model size with system throughput. A 7B model with a 128k context KV cache can consume more GPU RAM during decode than a 70B model with short context."

1.1 — Tensors: The Only Data Structure

In one line: Neural networks do not understand text, audio, or images; they execute tensor matrix multiplications over n-dimensional array buffers.
TENSOR SHAPES IN TRANSFORMERS
Input Shape: [Batch Size B, Sequence Length T]
  ↓ Embedding Layer
Hidden State: [B, T, Hidden Dimension d_model]
  ↓ Linear Projection (Q, K, V)
Attention Matrix: [B, Heads H, T, T]
  ↓ Output Layer
Logits Tensor: [B, T, Vocabulary Size V]
NUMERICAL MEMORY FORMULA

To store a tensor of shape $[B, T, D]$ in precision $\text{BytesPerElement}$:

$$\text{RAM} = B \times T \times D \times \text{BytesPerElement}$$

For $B=32, T=4096, D=8192$ in FP16 (2 bytes):

$$\text{RAM} = 32 \times 4096 \times 8192 \times 2 = \mathbf{2.14 \text{ GB}}$$ (Hidden state buffer alone).

FAILURE MODE
Out-Of-Memory (OOM) caused by unpadded dynamic tensor shapes forcing frequent memory re-allocation on GPU.

1.3 — Embeddings and the Geometry of Meaning

In one line: An embedding maps a discrete token or document into a continuous dense vector space where spatial distance equals semantic similarity.
VECTOR DISTANCE METRICS

Cosine Similarity (Normalized vectors, range -1 to 1):

$$\text{CosSim}(\vec{u}, \vec{v}) = \frac{\vec{u} \cdot \vec{v}}{\|\vec{u}\| \|\vec{v}\|}$$

Dot Product (Unnormalized magnitude sensitive):

$$\text{Dot}(\vec{u}, \vec{v}) = \sum_{i=1}^d u_i v_i$$

1.4 — The Transformer, Honestly Explained

In one line: Self-attention allows every token to query every other token in the sequence to dynamically update its context vector.
ATTENTION MATHEMATICS
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$ 
1. Project X → Query Q, Key K, Value V matrices
2. Compute similarity scores = Q × K^T
3. Scale by 1/√d_k to prevent gradient vanishing
4. Apply Softmax → Attention Weight Matrix (T × T)
5. Weight Value vectors = Softmax × V
COMPLEXITY BOTTLE-NECK

Self-attention requires computing a $T \times T$ matrix, creating quadratic scaling:

$$\text{Compute Complexity} = O(T^2 \cdot d)$$
FAILURE MODE
Doubling sequence length $T$ increases attention compute and KV cache RAM by 4x.

6.6 — Hybrid Search: Why Dense Alone Fails

In one line: Dense vector search captures semantic concepts but misses exact keyword matches (part numbers, IDs, acronyms); hybrid search combines Dense + Sparse (BM25).
RECIPROCAL RANK FUSION (RRF)

Combines sparse BM25 rank order and dense vector rank order without requiring score normalization:

$$\text{RRF\_Score}(d) = \sum_{m \in \{\text{dense, sparse}\}} \frac{1}{k + r_m(d)}$$

Where $k=60$ is a constant, and $r_m(d)$ is document rank in system $m$.

SEARCH METHOD COMPARISON

SAY THIS
"Dense vector search is blind to exact alphanumeric part numbers and rare error codes. Production RAG must always pair dense embeddings with BM25 sparse keyword search fused via Reciprocal Rank Fusion."
