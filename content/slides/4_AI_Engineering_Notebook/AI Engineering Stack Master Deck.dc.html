0.4 — The Vocabulary Bootstrap

In one line: Clear engineering requires crisp definitions — know the difference between parameters, tokens, context, and KV cache.
CORE MODEL PARAMETERS & TOKENS

Parameters ($P$): The learned floating-point weights (e.g. 70B parameters = 70B numbers storing pattern knowledge).

Token: Sub-word atom of text (~0.75 English words). Models operate exclusively on token IDs.

Context Window ($N$): Maximum tokens processed in a single forward pass (e.g., 128k, 1M, 2M).

SERVING & COMPUTE TERMS

Prefill Phase: Processing input tokens in parallel. Compute-bound (FLOP heavy).

Decode Phase: Generating output tokens auto-regressively (1 token at a time). Memory-bandwidth bound.

KV Cache: Memory storing key-value activations for prior tokens to avoid $O(N^2)$ recomputation.

"Do not conflate model size with system throughput. A 7B model with a 128k context KV cache can consume more GPU RAM during decode than a 70B model with short context."

1.1 — Tensors: The Only Data Structure

In one line: Neural networks do not understand text, audio, or images; they execute tensor matrix multiplications over n-dimensional array buffers.
TENSOR SHAPES IN TRANSFORMERS
Input Shape: [Batch Size B, Sequence Length T]
  ↓ Embedding Layer
Hidden State: [B, T, Hidden Dimension d_model]
  ↓ Linear Projection (Q, K, V)
Attention Matrix: [B, Heads H, T, T]
  ↓ Output Layer
Logits Tensor: [B, T, Vocabulary Size V]
NUMERICAL MEMORY FORMULA

To store a tensor of shape $[B, T, D]$ in precision $BytesPerElement$:

\text{RAM} = B \times T \times D \times \text{BytesPerElement}

For $B=32, T=4096, D=8192$ in FP16 (2 bytes):

$\text{RAM} = 32 \times 4096 \times 8192 \times 2 = 2.14 \text{ GB}$ (Hidden state buffer alone).

Failure Mode: Out-Of-Memory (OOM) caused by unpadded dynamic tensor shapes forcing frequent memory re-allocation on GPU.

1.4 — The Transformer, Honestly Explained

In one line: Self-attention allows every token to query every other token in the sequence to dynamically update its context vector.
ATTENTION MATHEMATICS
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
1. Project X → Query Q, Key K, Value V matrices
2. Compute similarity scores = Q × K^T
3. Scale by 1/√d_k to prevent gradient vanishing
4. Apply Softmax → Attention Weight Matrix (T × T)
5. Weight Value vectors = Softmax × V
COMPLEXITY BOTTLE-NECK

Self-attention requires computing a $T \times T$ matrix, creating quadratic scaling:

\text{Compute Complexity} = O(T^2 \cdot d)
Failure Mode: Doubling sequence length $T$ increases attention compute and KV cache RAM by 4x.

1.5 — Decoding: How the Next Token Is Chosen

In one line: Models output raw logit probability distributions; temperature, Top-P, and min-p govern the sampling algorithm.
SAMPLING PARAMETERS

Temperature ($T$): Scales logits $z_i / T$ before softmax. $T \to 0$ becomes deterministic greedy choice; $T > 1$ increases randomness.

Top-P (Nucleus): Samples only from the smallest set of tokens whose cumulative probability exceeds $P$ (e.g. 0.9).

Min-P: Filters out tokens with probability less than $P_{min} \times P_{max}$. Superior to Top-P in 2026.

1.7 — LoRA and QLoRA: Fine-Tuning You Can Afford

In one line: Low-Rank Adaptation freezes base model weights and trains low-rank decomposition matrices, reducing trainable parameters by 99%.
LORA MATHEMATICS

For base weight matrix $W_0 \in \mathbb{R}^{d \times k}$, update $\Delta W$ is factorized into rank $r$ matrices $A$ and $B$:

W = W_0 + \Delta W = W_0 + \frac{\alpha}{r} (B \times A)

Where $A \in \mathbb{R}^{r \times k}, B \in \mathbb{R}^{d \times r}$ with rank $r \ll \min(d,k)$ (typically $r = 8$ or $16$).

1.8 — Scaling Laws and Why the Curve Bent

In one line: Chinchilla scaling laws dictated optimal token-to-parameter ratio ($20:1$), but inference-time compute changed the scaling paradigm.
PRE-TRAIN SCALING (CHINCHILLA)

Loss $L$ scales as power law over compute budget $C$, parameters $N$, and data tokens $D$:

L(N, D) = \left(\frac{N_c}{N}\right)^{\alpha} + \left(\frac{D_c}{D}\right)^{\beta}

For compute optimal training: $D \approx 20 \times N$. (Over-training on 100x tokens yields smaller, faster inference models).

INFERENCE-TIME SCALING (SYSTEM 2)

Instead of scaling pre-train parameters $N$, scale Monte Carlo search / Chain-of-Thought tokens at inference time:

Pre-train Scaling:  High fixed cost, static answers
Inference Scaling: Dynamic search compute per query

4.2 — The KV Cache: The Real Capacity Constraint

In one line: Storing key-value attention vectors for previous tokens prevents $O(N^2)$ recomputation but dominates GPU VRAM memory.
KV CACHE MEMORY FORMULA

For model with $L$ layers, $H_{kv}$ key-value heads, dimension $d_k$, sequence length $T$, batch size $B$ in FP16 (2 bytes):

\text{KV Cache Bytes} = 2 \times B \times T \times L \times H_{kv} \times d_k \times 2

For Llama 3 70B ($L=80, H_{kv}=8, d_k=128$) at $T=8192, B=16$:

$\text{KV RAM} = 2 \times 16 \times 8192 \times 80 \times 8 \times 128 \times 2 = \mathbf{42.9 \text{ GB VRAM}}$

OPTIMIZATION ARCHITECTURES

Multi-Query Attention (MQA): Shares 1 KV head across all query heads ($8x$ KV RAM reduction).

Grouped-Query Attention (GQA): Groups query heads to $H_{kv}$ heads (Used in Llama 3 for optimal balance).
