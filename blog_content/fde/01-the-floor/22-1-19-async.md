## § 1.19 — Async

A waiter takes table 1's order, walks it to the kitchen, and then just *stands there staring at the oven* until the food is done, while tables 2 through 8 starve. Absurd — yet that's synchronous code. When you call an LLM API, which takes 2 to 30 seconds, sync code freezes the entire program to wait.

**Async** is the sane waiter: fire the order, serve other tables, come back when the kitchen bell rings. AI applications are *made of* long waits, which is why every serious AI codebase is async.

**The one distinction that matters.** CPU-bound work means crunching numbers — your code is busy. **IO-bound** work means waiting on network or disk — your code is *idle*. LLM calls, embedding calls, database queries, web fetches: all IO-bound. Async is the tool for IO-bound concurrency: one thread, many tasks paused mid-wait, an **event loop** juggling them.

```python
import asyncio

async def call_llm(prompt: str) -> str:      # async def → a coroutine
    await asyncio.sleep(2)                    # stand-in for a real API call
    return f"answer to: {prompt}"

async def main():
    answers = await asyncio.gather(           # run all three CONCURRENTLY
        call_llm("q1"), call_llm("q2"), call_llm("q3")
    )                                         # 2 seconds total, not 6
    print(answers)

asyncio.run(main())
```

**OUTPUT** (after about 2 seconds, not 6)
```
['answer to: q1', 'answer to: q2', 'answer to: q3']
```

**MENTAL TRACE.** `asyncio.run(main())` starts the event loop and hands it `main`. Inside, `asyncio.gather` starts all three coroutines. The first one immediately hits `await asyncio.sleep(2)` and says to the loop: *pause me, go do something else*. The loop moves to the second, which does the same, then the third. Now all three are parked, and roughly two seconds later all three wake and return. `gather` collects the results **in the order you passed them**, not the order they finished — which matters when you're fanning out over a list and need to line results back up with inputs.

Total wall-clock: about 2 seconds. Sequentially it would have been 6.

**Decoder ring.** `async def` marks a function pausable. `await` means "pause me here, event loop — go run someone else, resume me when this finishes." `asyncio.gather` starts all of these and gives you all results. `asyncio.run` starts the loop.

**The two laws.** You can only `await` inside `async def`. And calling a coroutine without `await` does *nothing* — you get an unrun coroutine object.

```python
async def call_llm(prompt: str) -> str:
    await asyncio.sleep(2)
    return "done"

async def main():
    result = call_llm("q1")     # ← missing await
    print(result)

asyncio.run(main())
```

**OUTPUT**
```
<coroutine object call_llm at 0x7f3a1c0d4e40>
RuntimeWarning: coroutine 'call_llm' was never awaited
```

**MENTAL TRACE.** Calling `call_llm("q1")` builds a coroutine object — a *plan* to do work — and hands it back. Without `await`, nobody ever executes the plan. So `result` holds the plan itself, `print` shows its memory address, and Python warns you on the way out that a coroutine was created and never run. **This is the number one async bug and the warning text is the tell.** When you see `never awaited`, you have a missing `await`.

The number two bug: putting a *blocking* call inside async code — `time.sleep`, or the synchronous `requests` library. It freezes the whole event loop and every table starves again. Use async-native libraries like `httpx` or `aiohttp`, or push stubborn synchronous code onto a thread with `asyncio.to_thread`.

**The production guardrail.** Firing 500 concurrent calls at an API triggers rate limits and gets you throttled or banned. Real code bounds concurrency with `asyncio.Semaphore` — a permit system where only N tasks hold a permit at once, and the rest queue.

**THE DEPLOYMENT LENS.** At Meridian this is not a performance nicety. You will need to embed thousands of document chunks during ingestion. Done sequentially at 200ms per call, 20,000 chunks takes over an hour. Done concurrently with a semaphore of 10, it takes minutes.

More importantly: **Meridian's rate limits will be lower than you expect, and you will not be told what they are until you hit them.** Bounded concurrency is not an optimisation you add later. It is the thing that stops your first ingestion run from taking down a shared API quota that another team is also using — which is a meeting you very much do not want in week three.
