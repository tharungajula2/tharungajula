Binary classification · imbalance · neural networks

Bank customer churn

Objective: identify customers likely to exit within six months so retention effort can focus on the highest-risk group.

Raw customers10,000
Churn rate20.37%
Baseline recall0.48
SMOTE recall0.75
SMOTE precision0.51
ROC-AUC0.8515
01Frame targetExited = 1 means the customer churned; this is a binary classification problem.
02Prepare dataDrop IDs, encode categories, scale numeric inputs and use a stratified train/test split.
03Train network11 inputs → hidden layers with ReLU → sigmoid output probability.
04Compare variantsSGD → Adam → dropout → tuning → SMOTE for class imbalance.
05Choose metricAccuracy is misleading because 79.63% can be achieved by predicting “stay” for everyone.
06Select trade-offSMOTE increases churn recall to 0.75 while precision falls to 0.51.
07Business decisionHigher recall is sensible when missing a churner costs more than an extra retention contact.
08Production improvementTune the probability threshold to outreach cost rather than treating 0.50 as fixed.

Core formulas

z = wᵀx + b
Neuron: weighted inputs plus bias.
ReLU(z) = max(0,z)
Hidden layers: add non-linearity.
p = 1 / (1 + e−z)
Sigmoid: turn final score into 0–1 probability.
BCE = −[y log p + (1−y) log(1−p)]
Loss: penalises confident wrong probability predictions.
Recall = TP / (TP + FN)
Capture: of all actual churners, how many are found?
Precision = TP / (TP + FP)
Purity: of all flagged churners, how many truly churn?

60–90 sec walkthrough

The project starts from 10,000 bank customers and predicts whether each customer exits. Because only about one in five churns, accuracy alone is not useful—a model predicting “stay” for everyone already scores 79.63%. After encoding/scaling the features, a small feed-forward neural network converts the inputs into a churn probability. The project compares SGD, Adam, dropout and tuned variants, then applies SMOTE only to the training data. That changes the operating trade-off: churn recall rises from 0.48 to 0.75 while precision falls to 0.51. The key lesson is that model selection follows the cost of mistakes; for low-cost retention outreach, missing fewer churners can matter more than overall accuracy.

BackpropagationPropagates loss gradients backwards so each weight receives an update signal.
OptimizerRule that updates weights. SGD uses a direct gradient step; Adam adapts updates using running gradient statistics.
EpochOne full pass through the training set.
DropoutRandomly disables units during training to reduce over-reliance on individual neurons.
SMOTECreates synthetic minority examples between minority neighbours; training set only, never test set.
ThresholdProbability cut-off turning p(churn) into a 0/1 action. It is a business choice, not a law of the model.

Scope notes

  • Outlier removal before the split is a weakness in the notebook; a production pipeline would learn preprocessing from training data only.
  • SMOTE improves recall but creates more false positives; the best choice depends on retention economics.
  • The tuned model has slightly stronger overall discrimination, while the SMOTE model is selected for the recall objective.
Univariate forecasting · trend · seasonality

Antidiabetic prescription forecasting

Objective: forecast a monthly demand series while preserving time order, seasonal structure and honest future-period validation.

Observations204 monthly
Train / test168 / 36
Candidate models625 SARIMA
Selected(2,1,3)(1,1,3)₁₂
Seasonal naive MAPE12.69%
SARIMA MAPE7.90%
01Inspect sequenceMonthly series shows upward trend plus a repeating annual pattern.
02Keep chronologyFirst 168 observations train; last 36 are future holdout. No random shuffle.
03Test stationarityADF: raw p=1.0; after d=1 p=0.1167; after seasonal D=1 at lag 12 p=0.0.
04Search orders625 combinations of p,q,P,Q ranked using AIC.
05Fit SARIMASelected SARIMA(2,1,3)(1,1,3) with annual seasonality m=12.
06Check residualsLjung–Box and diagnostics ask whether predictable autocorrelation remains.
07Roll forwardForecast 12 months, add later history, repeat across the 36-month holdout.
08Beat baseline7.90% MAPE versus 12.69% seasonal-naive MAPE.

Core formulas & intuition

Δyₜ = yₜ − yₜ₋₁
Regular differencing: remove trend-like level movement.
Δ₁₂yₜ = yₜ − yₜ₋₁₂
Seasonal differencing: remove a repeating annual level pattern in monthly data.
SARIMA(p,d,q)(P,D,Q)ₘ
Model notation: non-seasonal AR/I/MA + seasonal AR/I/MA.
AIC = 2k − 2 ln(L)
Selection: balance fit against parameter count; lower is preferred among candidates.
MAPE = mean(|(y−ŷ)/y|) × 100
Error: average percentage miss.
Residual = actual − forecast
Validation: remaining errors should have little predictable structure.
Concept visual · not a project data plot
60–90 sec walkthrough

The series contains 204 monthly prescription observations. Because future values depend on the sequence, the split stays chronological: 168 observations for development and 36 for future testing. Visual inspection shows trend and annual seasonality. ADF testing supports one ordinary difference and one seasonal difference at lag 12, so the candidate family becomes SARIMA(p,1,q)(P,1,Q)₁₂. A grid over 625 order combinations uses AIC to select a candidate, then residual diagnostics and Ljung–Box check whether predictable structure remains. The final model is evaluated with rolling 12-month forecasts and beats a sensible seasonal-naive baseline: 7.90% MAPE versus 12.69%.

TrendLong-run rise/fall in the level of a series.
SeasonalityPattern repeating at a known frequency; here annual repetition in monthly data.
StationarityStatistical structure stable enough for classical ARIMA-style modelling assumptions.
ADFAugmented Dickey–Fuller test; low p-value supports rejecting a unit-root/non-stationarity null.
AR / MAAR uses past values; MA uses past forecast errors/shocks.
Ljung–BoxTests whether residual autocorrelations are jointly different from zero.

Scope notes

  • One historical univariate series; no exogenous demand drivers are modelled.
  • AIC narrows the candidate set; residual behaviour and out-of-sample performance are still required.
  • MAPE is the notebook metric; production forecasting would typically add uncertainty intervals and additional error measures.

NIFTY 100 portfolio study

Objective: combine assets into a portfolio with a better return/risk trade-off, rather than predict which single stock will win.

Usable stocks82
Return matrix609 × 82
Simulations10,000
Equal-weight return9.6%
Best return / vol15.27% / 19.81%
Best score0.7707
01Define universeStart with NIFTY 100 constituents mapped to Yahoo Finance symbols.
02Collect pricesDownload adjusted close history; 82 stocks survive into the aligned usable panel.
03Convert to returnsPrices become daily log returns so assets are comparable.
04Estimate riskAnnualised mean returns plus covariance matrix describe expected reward and joint movement.
05Set baselineEqual weight provides a transparent diversified reference portfolio.
06Generate weights10,000 random positive weight vectors are normalised to sum to 1.
07Score portfoliosCompute expected return, volatility and simplified return/volatility score.
08Read frontierRisk-return cloud shows efficient-frontier intuition; best simulated score is selected.

Core formulas

rₜ = ln(Pₜ / Pₜ₋₁)
Log return: relative price change on a comparable scale.
E[Rₚ] = wᵀ μ
Portfolio return: weighted expected asset returns.
Var(Rₚ) = wᵀ Σ w
Portfolio variance: includes covariance across every asset pair.
σₚ = √(wᵀ Σ w)
Volatility: standard deviation of portfolio returns.
score = E[Rₚ] / σₚ
Notebook objective: Sharpe-style return per unit of volatility, without explicit risk-free subtraction.
Σ wᵢ = 1,   wᵢ ≥ 0
Simulation constraint: fully invested, long-only weights.
Efficient-frontier intuition · concept visual
60–90 sec walkthrough

The project begins with the NIFTY 100 universe and builds an aligned price panel with 82 usable stocks. Adjusted prices become daily log returns; from those returns, annualised mean return and covariance estimates are calculated. An equal-weight portfolio provides a simple baseline. The study then samples 10,000 long-only weight vectors, normalises each to sum to one, and computes portfolio return, volatility and a simplified return-over-volatility score. The best simulated portfolio shows the strongest risk-adjusted trade-off among those samples: about 15.27% expected return, 19.81% volatility and a 0.7707 score. The central concept is covariance—portfolio risk depends on how assets move together, not only on each asset’s standalone volatility.

CovarianceMeasures how two assets move together; the cross-asset ingredient behind diversification.
DiversificationCombining imperfectly correlated assets so portfolio risk can fall.
Variance vs volatilityVariance is squared dispersion; volatility is its square root and is on the same scale as returns.
Efficient frontierBoundary of portfolios offering the highest expected return for a given risk, or lowest risk for a return.
Monte CarloRepeated random sampling; here used to explore 10,000 possible weight vectors.
WeightFraction of total capital allocated to each asset.

Scope notes

  • The score is return/volatility; it is not a full Sharpe ratio with an explicit risk-free rate.
  • Random search gives an educational approximation, not proof of the exact optimum in 82 dimensions.
  • Roughly three years of history, historical mean/covariance estimates, no transaction costs and no institutional constraint set.

What L1 / L2 / tracking error mean

L1 distance = Σ |wᵢ − wᵢ*|
L1: penalises absolute deviations from target weights; often encourages fewer/sparser adjustments.
L2 distance = Σ (wᵢ − wᵢ*)²
L2: penalises larger deviations more strongly and spreads adjustments more smoothly.
Turnover ≈ Σ |wₜ − wₜ₋₁|
Implementation cost proxy: how much portfolio weight is traded between rebalances.
TE = sd(Rₚ − R_b)
Tracking error: volatility of active return versus the benchmark.
IR = mean(Rₚ − R_b) / TE
Information ratio: benchmark-relative return per unit of active risk.
Rₚ−R_f = α + β(R_m−R_f) + ε
CAPM regression: separates market sensitivity β from unexplained intercept α.

Why cvxpy appears

cvxpy is a Python modelling layer for optimisation problems. Instead of manually choosing every new weight, the code states an objective (“stay near target weights / reduce turnover”) plus constraints (“weights, turnover, tracking-error rules”), then a solver finds a feasible set of weights.
60–90 sec walkthrough

The client supplied the datasets and the strategy ideas; the implementation work turned those ideas into four Python frameworks. The backtest uses a US CRSP 500 universe over ten years and explicitly handles survivorship through date-appropriate tradable universes. Stocks are filtered and factor-ranked, with sector-neutral logic to prevent a factor signal from becoming an unintended sector bet. Rebalancing logic adds implementation lags and buffers. Target weights are then adjusted using constrained optimisation—L1 and L2 formulations in cvxpy—to control turnover, while benchmark-relative tracking-error logic can reduce active exposure. A separate robustness layer evaluates Sharpe, Sortino, drawdowns, tracking error, information ratio, rolling metrics, CAPM/multifactor regressions and sector contribution.

FactorA systematic stock characteristic used to score/rank securities, such as value, momentum or quality.
Sector neutralRank/construct within sectors so stock selection is not simply a sector allocation.
Survivorship biasBacktest error from using only securities that survive to the end instead of those tradable at each historical date.
Rank bufferKeep borderline holdings when their ranking moves only slightly, reducing unnecessary trades.
SortinoReturn relative to downside volatility rather than total volatility.
DrawdownPeak-to-trough decline in portfolio value.

Scope notes

  • Strategy concepts and datasets were supplied by the client; implementation and testing framework were built in Python.
  • US CRSP universe; no transfer of backtest claims to Indian markets.
  • The supplied work-learning document supports the framework mechanics, not a headline performance return; no result is invented here.
