Ponder Technical Architecture

1. Technical Ingestion Pipeline
Ponder processes input through the following structured sequential pipeline:
  - Phase A: Intake (Drag-and-drop or raw text paste. Supports up to 5 documents, 50,000 character limit per document, .txt or .md formats).
  - Phase B: Local Chunking (Sentence-window splitting. Uses 4 sentences per chunk with a 1-sentence overlap. Computes char, word, and chunk stats).
  - Phase C: Server-Side Vectorization (Calls Google Gemini text-embedding-004 through the Vercel AI SDK to compile 768-dimensional embeddings).
  - Phase D: Vector Store Memory (Stores vector nodes in an in-memory session-isolated singleton database).
  - Phase E: Live Agent reasoning loop (Sequentially invokes searchDocuments, analyzeChunks, and evaluateAnswer tools to construct an answer).

2. Memory and Database Persistence Policy
Ponder intentionally stores all vectors, chunks, and documents inside a serverless, session-isolated, in-memory singleton. It does NOT use any permanent database storage. When the visitor refreshes the page, terminates their session, or hits the reset/clear actions, all context is cleanly purged to maintain 100% security and zero persistence footprint.
