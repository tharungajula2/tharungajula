## § 1.16 — Git

Git is a time machine with parallel universes. Every **commit** is a snapshot you can return to forever. Every **branch** is a parallel universe where you experiment without endangering the main timeline. **Merge** brings a successful experiment home.

**The three rooms.** Every change moves through: **working directory** (your messy desk) → `git add` → **staging area** (the photo studio, where you *choose* what enters the next snapshot) → `git commit` → **repository** (the permanent album). Staging exists so one desk of changes can become several clean, single-purpose commits — the difference between a readable history and an archaeology dig. `git status` tells you which room everything is in. When lost: `status` first, always.

**The daily ten, understood not memorised:** `status` / `diff` (what changed) / `add -p` (stage by hunk — the pro move) / `commit -m` / `log --oneline --graph` (the timeline map) / `branch` / `switch -c feature-x` (new universe) / `merge` / `push` / `pull`.

A branch is just a movable sticker pointing at a commit. Creating one is free and instant, which is why the pro habit is: never experiment on `main`; every idea gets a branch; merge when proven; delete after.

**The undo table — memorise this and lose all fear:**

- Unstage a file → `git restore --staged f`
- Discard uncommitted mess → `git restore f` (careful: gone-gone)
- Fix the last commit's message or add a forgotten file → `git commit --amend`
- Safely undo a *pushed* commit → `git revert <sha>` (adds an anti-commit; history stays true)
- Move your branch pointer back in time → `git reset` (fine locally, dangerous on shared history)
- "I deleted my work!!" → `git reflog`, the secret journal of everywhere HEAD has been

Commits are almost never truly lost. Rule of thumb: **revert for public history, reset for private.**

**Merge conflicts, demystified.** A conflict is not an error. It's Git honestly saying "both universes edited the same lines; a human must choose."

```
<<<<<<< HEAD
DEFAULT_MODEL = "budget"
=======
DEFAULT_MODEL = "frontier"
>>>>>>> experiment
```

**MENTAL TRACE.** The markers show both versions. Above `=======` is what's on your current branch; below it is what's coming in from `experiment`. Git has not damaged anything and has not chosen — it has laid both options in front of you. You delete the markers and the line you don't want, leaving the truth. Then `git add` the file and `git commit`. That is all a conflict has ever been, and the fear of it is entirely manufactured.

**THE DEPLOYMENT LENS.** On a customer engagement you will often be working in *their* repository under *their* conventions, sometimes without push rights to anything but a branch. Two habits matter more than usual. **Commit messages are your paper trail** — when Marcus asks in month four why a threshold changed, `git log` should answer without you being in the room. And **never rewrite shared history on a customer's repo.** `revert`, not `reset`. The blast radius of getting that wrong on someone else's codebase is a category of embarrassment you only need once.
